## 真实模型只读验证

第一次验证在已存在的会话中失败：SDK 报 `Computer Use is unavailable for this node_repl session`，未执行 listApps、AX 或截图。该会话与启用插件的时序有关仍是待核实假设，尚未作为根因结论。

随后新建任务，明确加载 `computer-use:computer-use`，在同一个 cell bootstrap SDK。SDK 接入成功，首次 `listApps()` 返回 `desktop_locked`、`action_sent=false`、`dispatch_status=not_sent`。未执行后续 AX/截图或表单修改。10:10 左右的独立 OS 查询确认 `CGSSessionScreenIsLocked=true`，前台为 `com.apple.loginwindow`；同 bundle 新进程也返回 `desktop_availability=locked`。不能把该结果计为电脑操作成功，也不能据此降低锁屏保护。

产品 UI 自动化通过 SSH 回环 CDP 操作 KCode 自身；目标窗口和浏览器未使用 CDP/DOM 自动化替代原生 CUA。带调试参数的启动不计入 M02。

## 本轮源码回归

源码公共 MCP facade 原先存在两个已确认缺陷：`injectPermissionBrokerAgentMcpServers` 为空实现；resolver 按命令子串注入并把协议环境数组展开为对象。新增回归先观察到两项失败，再修复为匹配官方共享 `node_repl` 与 Host opaque authority，保留环境数组、用户参数和调用者配置，拒绝启动已退役独立 MCP。该兼容性修复不等同于证明第一次模型失败的根因。

本轮 CUA 工程测试 Node 12 项、Vitest 46 项通过；根类型检查通过；Lint 0 错误、533 条已有告警；CUA 专项 Lint 0 告警/错误；架构检查 0 违规。工程通过不能替代已安装 Release 的模型验证。

M2 对相同 75 个构建输入独立编译得到相同 source build ID `190dcf558c38b2285f5b`。随后工程测试发现一个夹具问题：传输懒启动测试用 `list_apps` 断言成功，在锁屏时把正确的 `desktop_locked` 误报成启动失败（11/12）。该测试改用不弹窗的权限事实查询，并继续验证 broker PID、实际终止后的新 PID 和同 runtime 重连；不取消或放宽生产锁屏检查。修订后本机与 M2 均通过 Node 12/12、Vitest 46/46；x64 源码编译通过，未运行 Intel 真机。

## 解锁后的真实模型与窗口操作

- M2 解锁后，GLM-5.3 通过已安装的 KCode 及官方 SDK 列出 13 个应用，读到测试夹具窗口的 AX 树。旧 Helper 多次在截图收尾返回 `cleanup_incomplete`。系统日志记录 stream 启动后停止请求返回 `-3808`，对象析构时框架仍认为流在运行。
- `f91f9845` 改为在 macOS 14 及以上的普通窗口使用 ScreenCaptureKit 单帧请求。M2 独立源码构建与生产包的 Helper build ID 均为 `f6897d78a9b137482309`。M2 CUA Node 13/13、Vitest 46/46 通过。已安装的签名 Release 在真实 GLM-5.3 工具回合取到测试窗口 2175 的原生 PNG，700 × 612 px、60,498 字节。截图来自该轮真实工具结果，窗口 PID 与 AX 一致。
- 首轮 Chrome 无网页 AX 控件。原生截图为 1200 × 977 px，当前 GLM-5.3 的 provider 请求未包含图像。隔离 Chrome 使用 Chromium 的 `--force-renderer-accessibility=complete` 启动后，取消的同一会话通过原生 CUA 重连，模型导航到本地测试页，填写带中文、emoji 和换行的内容，勾选，实际滚动到底，单次提交并回读“验收通过”。独立服务记录 `ok=true`，最大滚动 1,213 px，视口高 890 px，提交 1 次。此轮网页 AX 证据适用于显式开启该能力的测试实例。

## 双窗口释放、换代恢复和纯截图

- `9a1d1440` 统一同一窗口的按键和鼠标释放，记录持有阶段，关闭会话排空后回收操作明细，并在 IPC v3 握手后选择纯截图。初版签名候选包在 M2 成功取到 700 × 612 px 原生图。三组同窗采样的纯截图分别为 406、399、381 ms，树图联合观察为 407、419、417 ms。该采样只代表本夹具窗口。
- 初版在同一进程的兄弟窗口取得键盘焦点后取消，原窗口记录到 `keyDown`，兄弟窗口实际收到 `keyUp`。因此停止正式安装。补丁 `fa646b48` 在投递键盘事件前核对应用实际焦点；焦点转移时留存待释放记录。
- 最终候选 Helper build 为 `85e01e52025023a8a148`。本机与 M2 源码回归通过。M2 独立构建通过 Node 14/14 和 Vitest 49/49，使用同一 Helper generation 在解锁状态下实际完成 32,769 次应用列表观察，释放 16 个会话，用时约 113 秒。根类型检查和架构检查通过，Lint 0 错误、533 条已有告警。
- 用签名候选包和 GLM-5.3-Flash 在 M2 执行真实输入。长按后让兄弟窗口取得焦点，点击停止。兄弟窗口收到零事件，待释放记录仍在。夹具还原原窗口焦点后，同一会话读到 700 × 612 px 的纯截图，并用截图前的 AX 元素索引写入新值。原窗口收到一次松键，记录清除，独立观察与 AX 回读一致。
- 在另一轮长按确认已实际送达原窗口后，对专属测试 Helper 执行 `SIGKILL`。实测回执为 `cleanup_incomplete`、`possibly_sent`，原因 `helper_exited`。同一会话重新连接新 Helper。夹具记录原窗口只发生一次 `keyDown/keyUp`，新写入正确，随后鼠标 `mouseDown/mouseUp` 同样均落在原窗口，兄弟窗口为零事件。输入恢复记录已清除。
- 同一签名候选包的 GLM-5.3 通过原生 CUA 导航到隔离 Chrome 验收页。测试实例显式启用 Chromium 网页 AX。模型通过角色与完整标签填写、勾选、滚动并提交。独立服务记录实际滚动 1,213 px、到达页底和一次成功提交，中文、emoji、换行及勾选全部匹配。首次按钮匹配漏掉 AX 树缩进，修正后完成单次提交。
- 通过上述验收的同一 arm64 Release 已安装至 M2。安装归档摘要与签名候选包一致，主应用和 Helper 均通过严格签名校验，IPC 版本为 3。正常启动约 1.02 秒建立可见窗口。安装后辅助功能和屏幕录制均为 `granted`，未请求新授权。关闭了临时调试转发和验收专用进程。
