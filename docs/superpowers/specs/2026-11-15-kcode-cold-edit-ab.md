# 冷恢复首次编辑优化与真实模型 A/B

## 设计与验收

根因证据来自上一轮四次真实冷恢复：文件正文由 compact 附件恢复，首次 Edit 却都报未读取。源码合同明确补回读取状态只在内存；本批将完整补回的结构化快照随正文 text part 保存，再从 active 的可信 runtime 附件恢复。唯一状态所有者仍为 Runtime 的共享 `readFileState`；不在恢复时读磁盘认证新内容，不修改 Read/Edit/Write freshness、权限或 UI/V4 协议。

选择这一方案，是因为已有正文和真实读取证据足够完成恢复。仅加提示词提醒仍会产生重复 Read；在首次 Edit 中自动读取当前磁盘并放行会把模型未见过的内容当成已读。部分引用、截断、旧记录、缺少 freshness 字段和非可信附件仍不得直接编辑。事件顺序与持久化合同见 [Read File State Resume](../../../apps/zcode-cli/docs/design/v2/tool/17-read-file-state-resume.md) 及 [Rewind & Compact](../../../apps/zcode-cli/docs/design/v2/rewind-compact.md)。

回归先确认冷恢复读取状态为 0，再覆盖完整快照恢复、首次 Edit 成功、原有 stale 检查拒绝外部修改、可信来源与字段校验、active boundary、后续工具覆盖、部分引用不保存快照。现有 mtime / 大小优先及同内容容差保持；同 mtime 同大小变化的既有容差不在本批调整。

## 本轮 A/B 协议

A 为本批代码改动前 `38c40890`，B 为本批修复提交 `3624b0e5`。复用[上一轮协议](2026-11-15-kcode-real-model-ab.md)、同一 `codex/gpt-6.1-sol` / medium、三个 fixture、相同预算和外部断言。每场景两对，共 12 次任务；第一轮 B→A，第二轮 A→B。独立编译两版 Core，其他包保持一致，实验产物使用新目录，不复用上一轮结果或以重跑替换样本。

先比较任务验收与主动验证，再比较首次 Edit 的未读拒绝、冷恢复后的 Read、总请求、工具数、wire usage 和耗时。压缩场景仍是真实 `/compact` → 关闭 App → 冷恢复原 session → 原样“按刚才方案继续完成”。不提示模型避开首次 Edit，不改变任务输入以迎合修复。

## 结果

2026-11-15 23:26—23:43（Asia/Shanghai）完成全部 12 次真实模型任务，共 105 次 HTTP 请求。修复提交为 `3624b0e5`。A、B 均为任务 6/6、外部断言 54/54、主动验证 6/6，没有询问工具调用、HTTP 失败或摘要截断；每组都有两次正常摘要请求。

**定向结果：两次 B 冷恢复的首次 Edit 均直接成功，未读拒绝与恢复性 Read 均消失，任务约束和最终验收保持通过。** 两次 A 均先被拒，再重读 src 与 test 文件；B 接续阶段的第一个工具调用就是 Edit，并没有先用 Bash 或其他工具隐式读取文件。

## 实现、验证与证据

- 完整文件正文与同次读取的 snapshot 在同一 compact bundle 中持久化；快照只保存在 text part metadata 一份，未复制到 info metadata、未写进 provider 请求。恢复时不读取当前磁盘，实际编辑仍执行原有 freshness、partial、权限及写入 revision 校验。
- RED：两个 runtime 回归先复现恢复状态为 0；GREEN：原内容与 revision 恢复，首次 Edit 成功，mtime 前进的外部同长度修改仍被拒绝。另覆盖普通用户、非 synthetic、错误来源、provider 不可见、ignored、部分视图、范围、无 revision、旧版无快照、active boundary 及后续工具覆盖。
- Core 全量 321 文件：5,088 通过、21 跳过；完整 V4 冷恢复最终版本 124/124 通过（11.84 秒）；scripted E2E 7/7。根和 CLI typecheck 均通过（CLI 34/34）；根 lint 537 项既有告警、0 错误，CLI lint 88 项既有告警、0 错误及 4 项原样上游行数接纳。架构与修改文件格式检查通过。
- 产物位于 `.tmp/kcode-cold-edit-ab-20261115/`：`summary.json` 为统一重算指标；`runs/` 保存原始事件、脱敏 wire capture、验收与实际工作区副本；`verification/` 保存回归及门禁日志。四个脚本复用上一轮固定 fixture / App / capture proxy，额外统计冷恢复阶段；`variants/`、`A-revision.json`、`B-revision.json` 保留两版独立 Core 来源和实际加载路径。
