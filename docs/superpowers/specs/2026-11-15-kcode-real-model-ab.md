# KCode 真实模型 A/B

## 预先固定的协议

比较 A=`0549bd90`（本轮提示词与压缩实现前）与 B=`8586658a`。两版本之间的产品源码差异全部位于 CLI Core，因此分别从两个提交提取完整 Core、独立编译，通过进程级模块解析绑定选定版本；Bootstrap、Adapter、Provider 与依赖保持一致。记录编译来源与实际加载路径，避免误用当前版本产物。

模型采用本机已配置的 `codex/gpt-6.1-sol`，两组统一 `reasoningLevel=medium`、相同输出预算、权限与工具集。凭据只在内存使用；不将认证头、端点或个人配置写入产物。所有任务使用合成数据、独立工作区、临时 home 与数据库，关闭用户插件、技能、记忆、MCP 和标题生成，不读取个人会话。

三个固定场景各运行两对，顺序交替 B→A、A→B，共 12 次任务运行。每次限时 240 秒；不以重跑替换失败结果。模型可自行读取文件、修改代码和运行命令；不提示模型必须执行验证。

1. **普通修复**：修复时长解析器，兼容原调用方；固定验收覆盖单位、小数、零值、非法输入与公开 CLI。观察是否主动运行验证及处理边界。
2. **跨文件实现**：为订单统计增加状态过滤与金额排序，保留原入口和缺省行为；固定验收覆盖计算、过滤、排序、CLI 与文档。观察完成闭环、无谓询问及重复读取。
3. **压缩接续**：先调查折扣规则并仅给方案，再执行真实 `/compact`，关闭 App 并冷恢复原 session，用户只发“按刚才方案继续完成”。检查保留的业务约束、原文标记、工作状态与最终验证。正常摘要预算，不伪造 provider 返回或故障。

任务效果使用外部固定断言逐项判分，不依赖模型自评；完成率要求全部断言通过。效率记录墙钟耗时、真实 HTTP 请求数、主请求/摘要请求、工具调用数、provider usage（输入、输出、缓存命中分开）与失败/重试。主动性记录是否在无跟进催促下交付完整实现、主动运行验证，以及是否调用询问工具。只读或明确要求先给方案的阶段不以“主动改代码”加分。

保留完整任务输入、变更文件、脱敏 provider 请求/响应、事件与外部验收结果。先按预定口径给出逐对数据，再汇总；小样本只支持本轮观察，不宣称统计显著，也不把未触发的截断恢复、独立摘要模型差异或提交后故障当作收益。

计量口径：耗时从创建 App 到关闭 App，包含压缩场景的摘要与冷恢复，不含外部验收；真实 HTTP 次数包含失败请求。输入以 wire usage 的非缓存输入、缓存读取和缓存写入之和表示，同时分别报告非缓存输入；输出包含供应商计入的推理消耗，不按估算价格换算费用。工具数与主动验证统一从原始 `tool_call_started` / `tool_call_scheduled` 事件重算，避免初次采集器事件名及输入字段的计数误差；不改变模型输入、不重跑或替换样本。

### 可以确认的行为

- 首个主请求的 system 正文从 4,889 字符降至 4,552 字符，减少 337 字符（6.89%）；初始工具目录均为 23 个，内容哈希完全相同。所有主请求实际档位均为 medium、输出 cap 均为 8,192；所有摘要请求 cap 均为 4,096。
- 普通修复和跨文件实现都在一次用户指令后完成，并自行执行测试，没有调用询问工具。四次压缩任务都遵守先调查阶段，再在明确继续后实施；原有 fixture 文件在计划阶段保持不变，原 session 冷恢复、业务约束与 `REF-7Q2` 原文标记全部通过检查。
- 四次冷恢复都有一次首次 `Edit(src/checkout.mjs)` 被拒，错误为 `File has not been read yet. Read it first before writing to it.`；两组均自行重新读取后完成。它解释了一项共同的额外往返，本轮改动没有消除这一限制，不能把相应读取简单归为无谓重复。
- 外部 grader 在未修复的原始 fixture 上分别拒绝 7、6、6 项已知错误，避免空运行被判成功；最终 grader 读取公开 API、实际 CLI 和实际文件，不采用模型自报的完成状态。工具与验证计数从保存的事件统一重算。

### 解释与后续重点

本轮可以确认正常任务和手动压缩后冷恢复接续没有在这些样本上退化。现有提示词基线已经能主动实施和验证，成功率为满分，任务集存在明显的上限效应；这组数据无法证明主动性进一步提高。提示词精简与压缩的正确性修复可以保留，但收益说明应区分结构正确性和任务表现。

如果继续以效率为目标，下一项可验证问题是冷恢复后首次编辑前的定向重读，观察能否减少被拒后的恢复请求，并继续保留 Read/Edit freshness 校验。应在更复杂的真实仓库任务上扩大样本，再决定是否调整提示词；本轮不据这些小差异归因或回滚实现。
